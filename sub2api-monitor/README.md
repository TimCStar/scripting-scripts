# Sub2API 用量看板 · iOS Scripting

一个不依赖第三方中转服务的中文主屏幕小组件与手动重置面板。单一整面背景、文字和进度条使用黑白灰，适配浅色/深色；只有真实品牌图标保留原始颜色。默认首先显示标明「演示 · 虚构数据」的示例，不会联网。

版本：1.2.2。小组件保留真实平台图标、账号显示名称、额度及底部更新时间；不显示平台文字、标题、ID 或分组；新增每账号今日用量。

## 安装与配置

1. iPhone 安装 **Scripting**。将 `Sub2API-Monitor.scripting` 用「分享 → Scripting」打开并导入。`.scripting` 是根目录含 `script.json`、`index.tsx`、`widget.tsx` 的 ZIP 包。若系统没有自动识别，在 Scripting 的导入入口选择文件。也可在 app 新建项目，复制源码目录的全部 `.ts` / `.tsx` 文件及完整 `assets/` 目录。
2. 在 Scripting 中运行「Sub2API 用量看板」。填写服务器 HTTPS 地址，例如 `https://sub.example.com`。若部署于子路径，可填 `https://example.com/sub2api`；末尾 `/api/v1` 会自动移除。
3. 填写 Sub2API **上游账号**的数字 ID，以逗号分隔。顺序就是显示顺序，例如 `12,34,56,78`。最多配置 12 个。可以在管理后台查看账号 ID。
4. 选择管理员 API Key（`x-api-key`）或管理员 JWT（`Authorization: Bearer`），在安全输入框粘贴。这里需要管理员权限；普通下游转发 Key、普通用户登录 JWT 不适用。JWT 过期后需要手动更新。本工具不自动登录或刷新凭证。
5. 每个账号有独立「显示名称」输入框，留空沿用服务器名称；「5h 显示」可选自动、显示或隐藏。Pro 账号没有该窗口时可选择隐藏，不会按套餐名称一刀切。可先点「测试连接（只读）」，成功后点「保存并启用真实数据」。测试只检查前四个账号，不会保存凭证。保存会清除缓存并请求小组件刷新。
6. 长按主屏幕添加 Scripting 小组件，选择本脚本。小号显示 1 个账号，中号可选 1–2 个，大号可选 1–4 个。可在脚本内分别预览，并切换账号数量选项。
7. 可选：在小组件 Parameter 填已配置的账号 ID，例如 `34` 或 `56,12`，以单独选择/排序及设置数量。中号填 `34` 显示 1 个放大账号，填 `34,12` 显示 2 个；大号可填 1–4 个 ID。参数不得含凭证、URL 或 JSON。未知 ID 或超过此尺寸容量会显示错误，而不会悄悄截断或换账号。留空使用全局配置顺序的前 1 / 2 / 4 个。演示模式可选 101、102、103、104，例如 `101` 看放大 Codex，`101,102` 看双账号。

### 升级与账号设置

导入新包可能创建新的脚本项目。凭证及设置按脚本作用域保存，不能保证跨新项目保留；若创建新项目，请重新填写服务器、账号 ID 与凭证。请勿先删除旧项目；删除脚本可能删除其钥匙串项。安装包不包含个人设置或凭证。

### 1.2.2 请求状态与旧快照

- 「旧快照」只表示连接或账号请求失败后沿用曾成功读取的数据。服务器额度采样较早、手机刷新间隔经过，都不会单独触发该标签。无成功缓存时显示请求失败 / 暂无可用数据；恢复成功后清除失败状态。
- 完整面板新增「连接与请求状态」：未配置、尚未请求、正在读取、本次连接成功、失败及每账号部分失败，并提供只读刷新按钮。首次打开显示上次结果，不把历史成功说成持续在线。可读取全部已保存账号（每批最多 4 个）。输入区的测试结果单独显示，修改输入后需重新测试。
- 每账号分别显示成功读取账号时间和各额度窗口的服务器采样时间。「更新于」仍取所显示账号中最早的成功读取时间；请求失败不改为当前时间。上游采样与本机成功读取是不同时间，均不是实时连接保证。
- 今日 / 7d 统计或边界记录请求失败单独报告；不把成功读取的账号额度标成旧缓存，也不把未知金额当作 0。HTTP、权限、超时和网络原因仅显示固定安全描述，不显示原始响应、URL 或凭证。
- 保留 1.2.1 的字号、布局与金额安全检查。已过期的 7d 窗口仍隐藏美元金额并提示「待更新」；采样比例过旧时不推算总美元，今日金额继续受日期/时区/有效期保护。这些金额有效性判断不会触发「旧快照」。只做被动读取，不探测平台、不自动重置。

- 单窗口「标签 / 百分比 / 金额与倒计时」字号：小号 22/21/11，中号双账号 22/21/12，中号单账号 24/23/15，大号单账号 32/30/22，大号双账号 26/25/15，大号三/四账号 17/16/10pt。
- 双窗口按密度使用 13/13/9、20/19/12、25/24/18 或 15/14/10pt；账号名称增至 14–23pt；今日用量/更新时间从 8pt 增至 9–14pt。最拥挤的双窗口卡片使用 9pt 页脚，宽松单窗口使用更大的正文。
- 不扩大 7d 标签来保留旧超大百分比。保留每行缩放、原有安全内边距、单/双窗口结构、纵向居中与所有数据读取/刷新/重置行为。
- 回归覆盖全部尺寸和账号数、隐藏 5h、旧快照与未知值，包含保守高度和常见金额/倒计时宽度预算；这些不是 iPhone 原生像素测量，特别长的名称/金额及系统文字尺度仍需真机复测。

### 1.2.0 本机同步与自适应重排

- 刷新是让手机数据与 Sub2API 已有记录对齐：每次 iOS 实际执行小组件时间线，都重新 GET 所选账号及本地费用统计，不因手机缓存未过期而跳过。右上角按钮先尝试读取并请求重载；重载后的组件独立复读服务器，避免另一个执行上下文尚未持久化的缓存让界面退回旧数据。手动点击因此可能产生两批被动 GET；仍由 iOS 决定显示重载时机，默认请求下一次时间线为 20 分钟后。
- HTTP 请求增加 `Cache-Control: no-cache, no-store, max-age=0` 和 `Pragma: no-cache`。统计继续使用 `nocache=true`。这些操作只读 Sub2API 现有数据，不要求 Sub2API 查询平台、不改账号状态、不重置额度。额度值与采样时间使用本次服务器响应；不会把本机读取时间伪装成上游采样时间。1.2.2 起，采样较早不再触发「旧快照」，采样时间可在完整面板查看。
- 小组件和按钮共用读取/校验/提交路径。提交时重新读取最新缓存，并用请求开始时间尽量避免慢的旧请求覆盖较新的结果；相同选择及相同凭证的快速连点等待同一次读取，不再提前返回；不同账号选择或新凭证不会被旧请求吞掉。切换配置/凭证后丢弃旧请求结果。
- 离线时保留最后成功快照与时间并显示异常；缓存保存失败明确显示。Scripting 的 Storage 是异步持久化且没有事务/flush API，因此缓存合并不声称跨进程原子性；联网时每次时间线重新读取才是界面更新的保障。保持原有私有 Storage / Keychain 作用域，没有新增共享存储或凭证副本。
- 修正「今日用量刚读取却显示未知」：渲染时钟改为联网结束后的当前时间，新统计不会再被请求前的时间误判为未来数据。
- 单窗口和双窗口分别布局：仅 7d 使用完整数据区域并放大主要数值；窄卡双窗口上下排、宽卡双窗口并排。数据仍纵向居中，刷新按钮放在内容安全内边距内，保留黑白灰配色、真实图标与底部逐账号今日用量。
- 92 个逻辑/模拟网络测试、31 个模拟视图树检查、3 个 App Intent 检查、6 个异步小组件网络宿主检查通过。尚未进行真实 iPhone 视觉、交互或真实服务器验证。

### 保留的倒计时与手动刷新交互

- 保留 DATA 纵向居中以及标签靠左、百分比靠右。`7d` / `5h` 加粗放大（单窗口和双窗口分别按密度缩放），旧快照提示、金额、倒计时与页脚使用较小的次级样式。
- 今日用量移到组件底部，紧接在居中的「更新于」上方。多账号逐行保留「账号名 · 今日用量：百分比 / 金额」，不混成总额、不丢失任一账号；建议使用短且不同的本机显示名称。
- 不再显示绝对重置时间和「重置于」。每个额度窗口显示细线时钟与英文剩余时长，位于用量金额行右侧，例如 `5d10h`；不足一天为 `3h24m`，不足一小时为 `24m`，不足一分钟为 `<1m`，到期为 `0m` 并保留「待更新」，未知为 `—`。没有美元数据的 5h 仍显示自己的倒计时，不借用 7d 时间。
- 倒计时按本次渲染时间计算；是快照，不承诺逐秒或逐分钟跳动。手动刷新或 iOS 下次重载会重新计算，过期不会自行滚动到下一周期。
- 右上角刷新图标使用官方 `Button.intent` / `app_intents.tsx`。点击会立即尝试重新读取本组件所选账号的 Sub2API 本地记录（忽略仍新鲜的缓存），保存后请求 `Widget.reloadAll()`；演示模式只重载虚构数据。iOS 仍决定最终重载时机。刷新不会调用上游额度探测、推理、令牌刷新或消耗重置券；原有宽松布局的「重置…」入口与缓存券数仍保留，入口只打开应用内独立确认面板。
- 刷新参数只含账号选择及配置身份，凭证始终从本机 Keychain 读取。旧组件配置、未知/重复账号、凭证不匹配均不发请求；相同选择/凭证的并发点击在同一执行上下文等待同一次读取，跨上下文按上方 1.2.0 规则重新读取；请求期间切换服务器或凭证会丢弃旧结果。联网失败保留旧快照及其真实成功时间。
- 请在演示预览和实际主屏幕检查刷新按钮、长别名、两窗口和所有账号数量；模拟检查不是原生像素或交互保证。

### 今日用量统计

- 每账号增加「今日用量：百分比 / 金额」。金额取 Sub2API 本地记录的 `total_account_cost`（含账号倍率，美元），日期按设备 IANA 时区的本地自然日。百分比 = 今日金额 ÷ 有效 7d 估算总额 × 100，是费用比例估计，不是上游提供的日额度或日配额使用率。没有可用分母时显示 `— / $金额`，未知金额时显示 `— / —`，实测 0 保留为 0。
- 每次刷新增加每账号 1 次只读 `/admin/usage/stats`，显式传同一天 start/end、时区与 `nocache=true`。不使用服务器本地日 `today-stats`，不探测上游额度；统计失败不影响其他已读取额度。设备不能提供有效时区时不猜测今日数据。服务端需支持设备的 IANA 时区；上游接口对服务器不认识的时区会回退，因此极少见的新时区需要服务器时区库同步。
- 今日数据保存独立日期、时区与成功读取时间；跨日、切换时区、超过 60 分钟、账号连接失败或旧缓存无日期身份时隐藏金额和比例。跨日统计响应被丢弃；每次实际时间线均重新读取。今日统计失败不复用旧金额、不伪装成 0，也不篡改账号成功读取时间。
- 真实图标按密度放大：大号单账号 40pt，较宽布局 28pt，小号/中号双账号 24pt，大号 3–4 账号 20pt。紧凑双窗口缩小字号与垂直边距，金额和时间保持单行可缩放；仅 7d 的通栏和放大数据布局继续保留。

### 1.1.2 更新时间与留白优化

- 底部新增「更新于：M/D HH:mm」，使用设备本地时间。取当前显示账号中最早的成功读取时间；任一显示账号从未成功读取则显示 `—`。不会把渲染时间、失败请求时间或其他账号缓存写入时间冒充数据更新时间。
- 离线缓存回退保留原时间；多账号部分成功时，仍以最旧账号为准。这个时间表示本工具成功读取账号的时间，并非上游额度采样时间；连接或请求失败并沿用缓存时才标明「旧快照」，已过期窗口独立提示「待更新」。演示模式的时间只对应虚构数据。
- 中号单账号仅有 7d 时改为通栏，避免隐藏 5h 后保留双栏空位。大号单账号仅有一个窗口时放大百分比、金额与重置时间；多账号仍按密度收紧。1.1.2 当时将账号内容紧密排列；1.1.4 改为仅 DATA 区使用剩余高度纵向居中，标题与底部时间保持独立对齐。
- 1.1.2 当时未增加网络请求；1.1.3 的今日统计新增只读请求，手动重置和安全确认仍保持不变。配置页当前版本为「预览 · v1.2.1」。尚未在真实 iPhone 验证最终像素布局。

### 1.1.1 显示修正与确认

- 根容器使用官方示例的 `frame={Widget.displaySize}`，按实际宿主尺寸铺满整面背景；无内层卡片色块。外层不设 padding，内容间距独立放在内层（当前小号水平 14pt / 垂直 4–8pt，中号双账号含双窗口时水平 12pt / 垂直 8pt，其他 12pt）。没有硬编码某款 iPhone 的尺寸，也没有调用未文档化的 widget 边距开关。
- 1.1.1 曾显示绝对重置时间；1.1.5 已改为逐窗口英文倒计时，所有尺寸均保留。
- 图标先从 `provider-artwork.ts` 内嵌的原始 PNG 字节同步解码为 `UIImage`，完成后才调用 `Widget.present`；无需等待图片视图读取路径。如果解码失败，才尝试相同的本地 PNG 文件。两种模式都成功才传给 `Image.image`，不以假图标代替。
- 配置页预览区显示当前版本、3 个图标及解码结果。版本与诊断不放进小组件。更新后先确认版本，再检查三种尺寸的实际主屏幕显示；新建了脚本项目时需把小组件重新指向新项目。
- 旧版的 `Image.filePath` 写法本身属于官方支持 API；本次修改去除对运行时资源路径的依赖，并不能证明设备上缺图只有这一种原因。尚未在真实 iPhone 复测黑边与图标问题。

### 自适应信息密度

- 小号 1 个账号；中号 1 个账号时按窗口数选择通栏或双栏，2 个账号时并排紧凑卡。
- 大号 1 个账号时放大，2 个账号时双扩展卡，3–4 个账号时紧凑多行。
- 每张卡只显示离线真实平台图标、账号别名和额度。窗口进度下方的 7d 金额是「已用 USD / 估算总 USD」；小组件不堆叠解释文字。
- 每个窗口始终显示自己的倒计时；右上角只读刷新独立于原有宽松布局的「重置…」入口及缓存券数；该入口只打开应用确认面板，不直接重置。演示账号不能执行重置。
- 自定义名称及 5h 显示选择仅保存本机，不修改服务器账号。显示名称最长 40 字；短别名更适合紧凑布局。

## 看板里每个数字的含义

- **已用 %**：读取 OpenAI `codex_5h_*` / `codex_7d_*` 或 Claude 被动快照。Claude 的 0–1 比例换算成百分比。真实 0% 是正常数值；没有测量值显示未知，绝不伪造 0%。允许文字超过 100%，条形仅在绘制时封顶。
- **没有 5h 与未知**：OpenAI 没有观察到 5h 字段时，自动模式省略该行；这不等于已证明无限额。有真实窗口时即使 0% 仍正常显示。可按账号选择隐藏；强制显示但无数据时显示未知。不会凭 Pro 名称判断所有账号的限制。
- **7d 金额**：OpenAI / Claude 以当前快照重置时间减去 7 天为窗口起点，从 Sub2API 本地记录累计账号口径费用；完整 UTC 日期由 `/admin/usage/stats` 汇总，首个非完整日期由 `/admin/usage` 分页日志按实际起点过滤。金额口径含账号倍率。总额按 `已用费用 × 100 / 原生已用百分比` 自动估算，与上游管理面板公式一致。
- **估算的边界**：分母不是服务商承诺的余额或美元限额。其他实例产生的使用可能影响原生百分比，却不在本实例账单中；采样延迟及比例取整也会影响估算。不是今日费用或任意最近 7 天，更不是手动参考额度或剩余比例。
- **未知金额**：比例/费用为 0 时无法反推总额，总额显示 `—`；窗口、记录、时区、刷新状态或分页完整性无法确认时不伪造金额。首日超过 2,000 条记录会保守显示未知。比例快照旧时保留可核验的窗口已用费用，但不反推总额；已过期窗口不显示美元值。
- **Claude / Antigravity**：Claude 显示原生百分比；只有能确认 7d 重置点及完整本地费用时才显示相应金额。Antigravity 没有可安全读取的持久化额度快照时显示「暂无额度快照」，不把按模型余额包装成 5h/7d。
- **旧快照**：只用中性文字表示连接/请求失败后的缓存回退；0%、采样较早或经过刷新间隔不触发该标签。真实连接、请求或账号异常另行提示。底部显示成功读取时间；完整面板另列服务器采样时间，金额仍独立校验窗口有效性。
- **平台图标**：使用随包携带并内嵌于源码的真实品牌 PNG，先离线解码，适配浅/深背景。来源、商标说明和第三方图标代码许可证见 `assets/ATTRIBUTION.md`；不使用 SF Symbols 替代品牌标志。

账号之间的百分比不会相加，多分组账号不会重复计费。旧版手动参考额度不再用于显示。

**配置仅在当前脚本 Storage，凭证仅在本机 Keychain。** 不要分享设备存储备份、真实凭证或敏感账号截图。管理凭证具有较大权限，请只在可信设备使用。

## 安全与请求边界

小组件刷新和读取账号只请求以下 GET，且拒绝重定向：

- `/api/v1/admin/accounts/:id`
- `/api/v1/admin/usage/stats?account_id=…&start_date=…&end_date=…&timezone=…&nocache=true`（7d 完整日期用 UTC，今日统计用设备 IANA 时区）
- `/api/v1/admin/usage?account_id=…&start_date=…&end_date=…&timezone=UTC&exact_total=true&sort_by=id&sort_order=asc&page_size=500&page=…`

后两项只读取本实例记录，不是 `/accounts/:id/usage` 上游探测入口。原始日志不写入缓存，只保留核验后的金额。

小组件不会调用模型、消耗推理 token、探测 Responses、刷新登录态、提交修改或触发额度重置。特意不使用通用 `/accounts/:id/usage`、批量 usage、OpenAI `/quota`：当前上游这些入口可能探测模型、清除账号异常或触发已配置的重置行为。Antigravity 的兼容 five_hour 字段也不代表真正 5 小时额度。

### 手动 Codex 重置：明确确认，一次请求

1. 先保存真实服务器设置。展开卡点「重置…」，或直接打开脚本的「Codex 重置中心」。链接中的账号 ID 仅为选择提示，绝不是批准。
2. 点「读取账号与重置券（只读）」。仅 OpenAI OAuth 主账号提供操作按钮；其他平台、API Key 账号和 Spark 影子账号不支持。缓存的券数不是实时资格承诺。
3. 点对应账号「核对并重置一次…」。应用重新 GET 账号详情，再显示明确的确认框：服务器、账号名/ID、缓存券数，**不可撤销地消耗 1 次 Codex 重置券**，可能恢复账号限流状态并刷新缓存。不能选择只清 5h 或只清 7d；实际重置窗口由服务端返回。
4. 只有点「消耗 1 次并重置」才执行。确认后再检查一次账号身份/类型。先把 pending 收据同步写入本机 Keychain 并读回验证，随后向你配置的 Sub2API 发送**一次** `POST /api/v1/admin/openai/accounts/:id/reset-quota`，无请求体，无窗口选择参数，无自动重试。所有上游交互由你的 Sub2API 服务器处理；脚本不直接连接 OpenAI。
5. 成功显示重置窗口数。即使缓存刷新/账号恢复部分失败，也明确表示重置已完成，不能再次点击来「修复」。超时、连接中断、5xx、格式不明都显示「结果不确定」，并保留本机防重复锁；券可能已经消耗。
6. 到管理后台核对实际结果。只有你确认「已核对，解除本机锁」，才允许以后发起新的确认；解除本机锁本身不发网络请求。成功操作也保留锁，防止误连点。

收据按服务器地址和账号 ID 绑定，换凭证/重新保存配置不会自动解除；移除管理凭证不会删除这些防重复收据。操作中的同步本机锁与 pending 收据可防止当前进程重复点击和常见重启重试，但**服务端不提供客户端幂等键**。不要在多个设备或多个独立运行实例同时操作同一账号；本工具无法提供跨设备锁或保证异常退出后的 exactly-once。

本版本只实现及模拟验证这个功能，未连接真实账号、未消耗任何实际重置券。不可把安装或小组件链接当作一次真实操作的批准。

管理员凭证只存设备专用、首次解锁后可访问的钥匙串项（`first_unlock_this_device`、不做 iCloud 同步），不会进入脚本源码、URL、小组件参数、普通配置、缓存、日志或安装包。网络异常不回显原始服务端响应。服务端详情响应可能包含敏感字段；只有白名单显示字段被归一化并缓存，原始账号对象不落盘。

重启后尚未首次解锁、钥匙串读取失败、401/403、离线和服务端错误都会降级为缓存或设置提示。不支持 HTTP、自签名证书绕过、URL 里的用户名密码或查询参数。不跟随重定向，避免把管理凭证发到其他地址。

「移除本机凭证和缓存」会切到演示模式。删除脚本也会删除脚本作用域内钥匙串项。新服务器必须重新输入凭证，不能沿用旧服务器的凭证。

## 刷新与兼容范围

默认请求约 20 分钟后刷新；iOS 自行决定真正刷新时间，不能保证准点或后台常驻。缓存仅用于离线回退；每次真正执行时间线均重新读取。每次最多并行读取当前小组件可见的 1 / 2 / 4 个账号，小组件单请求超时 8 秒（应用内账号核对 12 秒，手动重置 45 秒）。失败保留每个账号的最后成功数据；不同尺寸/参数共享白名单缓存，但各自重新读取所选账号。

已依据 **Wei-Shaw/sub2api v0.2.15，commit `3a6fd1c9db07203ca308aaba69e502bc1f35b307`（2026-10-09）** 验证字段。兼容部署差异时采用「未提供」，不虚构数据。旧版没有当前 canonical Codex 字段时不推测 legacy primary/secondary 的意义。未配置或未观察到快照时，可通过正常业务使用让服务端自然采样，再等系统刷新；脚本不会主动制造使用量。

小组件的着色/强调模式由 iOS 管理：根背景使用 `widgetBackground`，会在该模式隐藏；图标设置 `widgetAccentedRenderingMode="fullColor"` 保留真实颜色。支持 standard systemSmall / systemMedium / systemLarge，锁屏/accessory family 未作适配。
